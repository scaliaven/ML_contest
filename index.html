Quick start

Two isolated environments — Spleeter pins an older TensorFlow that the PyTorch stack can't share.

1 · Training / inference (PyTorch)

# Python 3.9+
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

python main.py            # train / infer
python naive_ensumble.py  # ensemble → CSV

2 · Preprocessing (Spleeter)

python -m venv .venv-spleeter
source .venv-spleeter/bin/activate
pip install -r requirements_spleeter.txt

python voice_split.py                  # separate vocals
python data_processing/gray_scale.py   # .wav → .pt

⚠️ Scripts use absolute paths hard-coded to an HPC scratch directory (/scratch/hh3043/ML_contest/…). Update the dataset, checkpoint, and output paths before running elsewhere.

Under the hood

  • Input — the vocal stem becomes a [128, 130] mel-spectrogram, sliced to [128, 128] and reshaped to [1, 128, 128] — a single-channel image.
  • Adapted stems — for 128×128 input the first conv is changed to 3×3 stride-1 and the early max-pool is skipped, avoiding over-downsampling.
  • Augmentation — Mixup for the first half of training (then plain cross-entropy), plus SpecAugment (time & frequency masking) via torchaudio.
  • Optimization — SGD with momentum & weight decay, cosine-annealing (warm restarts), gradient-value clipping, best-val checkpointing.
  • Ensembling — naive_ensumble.py soft-votes ResNeXt-50 + DenseNet-201; meta_model.py stacks a meta-learner on the base outputs.

What worked

Key findings from the project report.

+ Signal

Grayscale > RGB

Single-channel spectrogram images outperformed RGB renderings.

≈ +2%

Mixup + SpecAugment

Combined augmentation added roughly two points of accuracy.

Winner

Unweighted ensemble

Summing probabilities beat a learned meta-model, which overfit.

Future
